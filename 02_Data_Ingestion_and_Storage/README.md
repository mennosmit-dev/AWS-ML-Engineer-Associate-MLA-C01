# 02 — Data Ingestion and Storage

## 🎯 Engineering Objective

Design scalable and secure data ingestion and storage architectures that
support machine learning workflows, including training, feature engineering,
and production inference systems.

This section focuses on selecting storage and ingestion strategies aligned
with workload requirements, governance constraints, and cost efficiency.

---

## 🧠 Capabilities Developed

- Selecting storage architectures (data lake vs warehouse vs lakehouse)
- Designing S3-based storage with versioning, lifecycle management, and access control
- Understanding ingestion patterns for batch and streaming ML workloads
- Evaluating storage decisions based on scalability, security, and cost tradeoffs
- Preparing datasets for downstream analytics and ML pipelines

---

## ☁️ AWS Services & Concepts Covered

- **Amazon S3**
  - Policies and access control
  - Encryption and security configuration
  - Versioning and replication
  - Lifecycle management
  - Access points

- **Storage Options**
  - EBS vs EFS vs FSx tradeoffs

- **Streaming & Real-Time Ingestion**
  - Kinesis Data Streams & Firehose
  - Managed Service for Apache Flink
  - Amazon MSK (Kafka) architecture and comparisons

---

## 🔗 Role in ML Engineering Workflow

Reliable data ingestion and storage form the foundation of cloud-based
machine learning systems, enabling:

- scalable training pipelines
- reproducible datasets
- real-time ML applications
- governed and secure data access
